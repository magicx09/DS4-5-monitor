# 原生双路音频：现场恢复与音量锁定修复

日期：2026-11-08。

## 已实测的结果

exp8 测试时，电脑音箱作为主输出，手柄没有声音；把主输出改成手柄后才有声。检查 Windows 音频会话与固件状态，记录如下：

- Windows Console/Multimedia 默认播放设备为外置音频设备；Communications 默认设备为 DualSense。
- 测试游戏同时在外置音频设备和 DualSense 上有 Active 音频会话，两个会话均未静音。
- DualSense 的 HID MI_03、音频 MI_00 和播放端点 ContainerId 一致。USB 音频为 48 kHz、4 通道。
- 手柄播放端点音量为 100%，未静音。
- WASAPI loopback 电平统计显示四个通道都有非零信号，前两通道混为单声道后没有明显反相抵消。测试未保存音频样本。
- 0xF5 固件计数表明 USB 收到音频并进行 Opus 编码、蓝牙发送；此次快照 raw/encoded/haptic 三类队列丢包均为零。发送计数不是播放确认。
- 唯一现场改动：NAudio 将 DualSense 端点音量从 100% 改为 90%，500 ms 后恢复 100%；没有改主输出、会话音量、音频路由、静音、固件或游戏设置。
- 随后实际听到了手柄音效。

这次测试中，游戏已在原生输出两路音频，重新下发 USB 音量后手柄恢复有声，因此后续修改集中在音量状态同步。故障发生前的原始 HID 输出没有抓到，具体是哪条控制报告导致静音仍未确定。

## exp9 做了什么

沿用 OLED 音频设置中的“锁定音量”选项及已保存的开关值。

此前这个选项只通过过滤主机 HID 允许位来阻止后续游戏音量写入；开启时没有恢复已被改低的功放。exp9 补充：

1. 开启锁定后，向 DS5/DSE 发送当前 USB 端点对应的扬声器/耳机功放音量。
2. 已开启锁定时，每次新连接并完成 USB 挂载后重发一次。
3. 蓝牙队列满时保留待发送状态，下一轮重试；成功后停止，不持续强制写音量。
4. 全状态回放也使用 USB 端点音量，避免重新带回开启锁定之前的游戏音量。
5. Windows 音量滑块仍有效；关闭锁定时游戏音量控制行为不变，取消未发送的恢复。
6. 恢复包只设置耳机/扬声器音量允许位，不修改音频路由、静音、麦克风或扳机。DS4 不运行这条 DS5 状态服务，其已验证音频路径不变。

恢复逻辑在固件内完成，适用于游戏原生输出的手柄音轨。

## 使用

**必须在 OLED → 音频设置中开启“锁定音量”，并按现有菜单方式保存。** exp9 不会自动把已保存的“关”改成“开”。

电脑音箱继续作为默认输出；DualSense 音频端点保持启用。若当前 exp8 经现场恢复已经有声，开启并保存锁定也能阻止后续游戏音量覆盖；exp9 进一步提供开启锁定时的自动恢复和重连恢复。
