# DS4 + DS5 中文 OLED 基础支持实验版

日期：2026-11-07。版本：`ds4-basic-exp1`。目标硬件：标准 4 MiB Pico 2 W，150 MHz，SH1107 OLED。

## 结论与完成状态

可以移植 snipem/DS4Dongle 的 DS4 协议实现，使同一份 home11 衍生固件连接真实 DS4 或 DS5/Edge，一次一个手柄。本次已完成基础控制代码、本机测试、两种中文布局固件构建及镜像检查。**未刷写设备，未完成 DS4 实机验收；这是实验版，不是已证明兼容全部 DS4 和 Windows 游戏的正式版。**

首版范围：按键、摇杆、触摸板、体感、普通震动、灯条。DS4 音频、耳机和麦克风不在本版范围内。DS4 本身没有 DualSense 的自适应扳机和原生触觉执行器，不把它们显示为已支持。

## 采用的源码与实现路线

参考版本固定为 [snipem/DS4Dongle 2b1e3078b8059c3be422052466cc03a71844edb5](https://github.com/snipem/DS4Dongle/tree/2b1e3078b8059c3be422052466cc03a71844edb5)。它是完整固件，不是可直接链接的独立库。它与 home11 同源于 DS5Dongle，因此可以复用协议和描述符，但不能把两个 `main`、蓝牙栈和配置模块一起编译。

本次保留 home11 的 SDK 2.3.1、BTstack、TinyUSB、Opus/WDL、配对槽、OLED 和 DS5 音频架构，移植 DS4 协议需要的部分。描述符和校准布局来源保留在 `repo/src/DS4Dongle-LICENSE.txt` 及源码注释中。没有新增需要安装的编解码依赖。

| 路径 | 已实现行为 |
| --- | --- |
| 配对 | 保留 DS5/Edge 名称筛选；实验开关开启时，接纳名称精确为 `Wireless Controller` 的 DS4 候选；保留四槽归属检查 |
| 初始化 | 读取 DS4 蓝牙特征报告 `0x05` 和 `0xA3`，校验 CRC 和所需长度后允许 USB 枚举；`0x05` 读取也使手柄进入完整输入模式 |
| 输入 | 接受标准 `A1 11`、79 字节完整蓝牙包，校验 CRC；将其中 DS4 状态送往 USB `0x01`，拒绝音频变体和异常触摸计数 |
| 触摸 | 保留 USB 能承载的三份完整历史；蓝牙四份历史时保留后三份；OLED 使用最新触摸点，按 DS4 的触摸板高度显示 |
| OLED／映射／校准 | 额外生成一份 DS5 布局的内部视图，供原有逻辑使用；向电脑输出时只把修改过的控制量和陀螺仪校正写回 DS4 原始报告，不误改时间戳、状态、加速度与触摸历史 |
| 体感特征报告 | DS4 蓝牙 `0x05` 转 USB `0x02`；调整陀螺仪正负校准值顺序；固件信息 `0xA3` 按 USB 长度补尾部 |
| USB 身份 | DS4 连接后为 `054C:09CC`、507 字节 DS4 HID 报告描述符；本版配置只有 HID，无 DS4 音频接口；不是完整复刻原装 DS4 的 USB 复合配置 |
| 普通震动／灯条 | USB `0x05` 转蓝牙 `0x11`，支持中断 OUT 和控制 SET_REPORT；保留普通震动、RGB、闪烁标志，清除音频使能标志；OLED 灯条模式和左右振动倍率接入 |
| 型号切换 | 蓝牙型号与当前 USB 身份分开保存；需要切换时先断开 USB，再延时重新枚举；电脑休眠时保留旧描述符，恢复后再切换 |
| 功能隔离 | DS4 不运行 DS5 的音频发送、特征写命令、扳机效果与语音流程；不适用的设置显示 `--` 并禁止修改；屏幕显示 DS4 型号 |

本版针对原厂 DS4 的标准协议评估。名称不是可靠的硬件鉴权，第三方仿制手柄及不同固件版本必须另做验收，不能因为名字相同就宣称兼容。

## 为什么音频另做

DS4Dongle 的声音路径为 32 kHz PCM → SBC → 蓝牙报告 `0x17`，不同于 DS5 的 Opus 路径。参考仓库 README 仍说麦克风未实现，但当前源码已有实验性 SBC 麦克风解码，并记录了双向音频下部分输入变体的布局异常。本版不引入这条不确定路径，也不向 Windows 暴露不能工作的 DS4 声卡。

## 保存区与原 home11

没有移动 config、slots、remap、calib 或 BTstack 保存区，也没有导入 DS4Dongle 的配置结构。配对槽原来的 32 字节前缀保持原样，只在其后追加 8 字节型号标记。旧记录无标记时继续按原 DS5 行为读取；成功识别并配对 DS4 后保存其型号，供断电后按 PS 重连使用。

主机测试确认：旧 home11 配对记录加载不会触发擦除，增加 DS4 槽不会改变另一槽的地址。原 home11 成品固件及其 SHA-256 文件未覆盖。若退回原 home11 并在那里保存配对槽，旧代码会丢掉新增型号元数据；再次使用实验版时，DS4 可能需要在自己的槽重新配对。不能把源码格式兼容测试等同于实机掉电安全认证。

## 本机编译

在本目录执行：

```powershell
python dev.py ds4
```

执行主机测试，构建 prop14/prop16，并运行保存区、RAM 驻留、XIP 检查；产物写入 `firmware/ds4-experimental/`。只构建一种布局可加 `--row 14` 或 `--row 16`。

普通构建的 `ENABLE_DS4` 默认关闭，实验构建明确打开。当前实验配置要求 `ENABLE_SERIAL=OFF`、`ENABLE_COMPANION_VENDOR=OFF`，因为 DS4 HID-only 配置尚未加入 CDC/管理接口。现有 SundayMoments 桌面软件不会因此自动兼容。

## 验证结果与边界

- 主机测试：349 个默认逻辑测试、21 个 prop14 中文测试、21 个 prop16 中文测试、1 个真实 USB 生命周期测试，共 **392 项通过**，启用 ASan/UBSan。
- 新增覆盖：截断输入、CRC、音频包拒绝、控制量往返、触摸历史边界、校准重排、震动／灯条输出标志、描述符报告长度、旧配对槽迁移、中文菜单及真实 `usb_power.cpp` 的休眠／换型流程。
- DS4 开启的 prop14/prop16：构建成功；镜像按扇区计截至 `0x10156000`，保存区开始于 `0x103F9000`，间隔 2700 KiB；RAM 驻留和 XIP 分频 2、电压码 11 检查通过。
- DS4 关闭的两种布局也完成回归构建与三项检查；原成品未覆盖。
- 输入／输出转换测试使用构造的协议数据，不是本机真实 DS4 抓包。未进行实机蓝牙配对、无线重连、Windows 游戏、端到端延迟、长时间稳定性或 RF 压力测试。

日志在 `logs/host-tests.log`、`logs/ds4-prop14-*`、`logs/ds4-prop16-*`、`logs/ds4-off-prop14-*` 和 `logs/ds4-off-prop16-*`。

## 后续实机验收

1. 确认使用标准 Pico 2 W；实验镜像不应直接当作 16 MiB Waveshare 板的构建。刷写前保留现有配置／完整闪存备份及原 home11 镜像。
2. 烧录 prop14 实验镜像后，在 OLED 中选择空槽；DS4 关机状态按住 **SHARE + PS** 直到灯条快闪，开启板端配对窗口。
3. 检查 OLED 显示 DS4；Windows 应出现 `054C:09CC` 的游戏设备，本版应没有新增 DS4 音频设备。
4. 检查所有按键、两摇杆、L2/R2 模拟量、双指触摸与点击、六轴、普通震动、RGB／闪烁；对照 USB 有线直连的行为。普通 `joy.cpl` 不足以验收触摸和体感，需使用支持 DS4 的测试程序或游戏。
5. 断电后按 PS 重连；切换到另一槽的 DS5，确认 DS5 音频、触觉和自适应扳机仍正常；再切回 DS4。
6. 检查休眠／恢复、断线时无卡键、两手柄同时开机时只接一个、至少 30 分钟持续输入与震动。发现问题先保留型号、症状与复现步骤，再决定是否抓包或增加调试构建。
